## 2026-09-11 · 速度环 · VirtualMotor 一阶模型

### 被控对象

`Common/config.h` 的 B6 段：

```
acceleration = motor_gain * input - damping * speed - load
             = 100 * input - 2 * speed - 0

传递函数： G(s) = motor_gain / (s + damping) = 100 / (s + 2)
直流增益  K  = 100 / 2 = 50       （单位输入对应的稳态速度）
时间常数  tau = 1 / 2  = 0.5 s
```

**为什么取 gain=100、damping=2：**

| 约束 | 计算 | 结论 |
|---|---|---|
| 机械时间常数要远大于控制周期（带宽分离） | tau = 1/damping = 0.5 s，控制周期 10 ms，比值 50 | ✅ 满足 |
| 任何合法目标都不能被输出限幅永久顶死 | 满输出稳态速度 = (100/2) × 100 = 5000 > `RC_MAX_TARGET_SPEED` = 3000 | ✅ 满足 |
| 观测窗口内能看到完整过渡过程 | tau = 0.5 s，阶跃整定约 1 s | ✅ 演示友好 |

### 控制周期

10 ms（`RC_CONTROL_PERIOD_MS`），`dt = 0.01f`。
**纪律**：改周期必须重算下方全部参数并更新本记录；`config.h` 里有 `#if` 编译期检查兜底。

### 参数推导（先离线算，再上仿真）

按二阶闭环设计，取 **阻尼比 zeta = 1.0（临界阻尼，理论无超调）**、**自然频率 wn = 10 rad/s**：

```
开环： L(s) = (kp + ki/s) * 100/(s+2)
特征方程： s^2 + (damping + motor_gain*kp) s + motor_gain*ki = 0

wn^2      = motor_gain * ki          -> 100 = 100 * ki   -> ki = 1.00
2*zeta*wn = damping + motor_gain*kp  ->  20 = 2 + 100*kp  -> kp = 0.18
```

| 参数 | 值 | 单位 | 依据 |
|---|---|---|---|
| `kp` | 0.18 | 无量纲 | 由 zeta=1、wn=10 反解 |
| `ki` | 1.00 | 输出/(误差·s) | 同上 |
| `kd` | 0.00 | 输出/(误差/s) | 对象是一阶无噪声模型，D 项只放大噪声、不改善相位裕度 |
| `output_limit` | 100.0 | 与执行器同量纲 | ICD §20 冻结值 |
| `integral_limit` | 100.0 | 误差·s | 取值规则 `output_limit / ki`，即积分项单独作用最多达到满输出（CR-002） |

### 实测结果（由 `tools/analyze_trace.py` 从原始 CSV 自动算出）

数据源：`docs/data/trace_normal.csv`，运行 `sim_demo.exe normal`。

| 阶跃 | 超调 (%) | 峰值 | 上升时间 (ms) | 整定时间 (ms) | 稳态误差 |
|---|---|---|---|---|---|
| 100 -> 1000 | 16.11 | 1145.0 | 90 | 570 | +0.000 |
| 1080 -> 1500 | 10.88 | 1545.7 | 70 | 510 | +0.000 |
| 1370 -> -800 | 14.50 | -1114.7 | 170 | 660 | -0.000 |
| 100 -> 600 | 10.72 | 653.6 | 70 | 510 | +0.046 |

**结论：**
- **稳态误差为 0** —— 积分项把静差消干净了，说明 `ki` 的量纲与实现一致；
- **超调 10.7% ~ 16.1%，而理论设计值为 0** —— 差距全部来自**输出饱和期间的积分累积**，
  即 ICD §7 冻结算法缺少条件积分抗饱和（CR-001）。这不是参数没调好，
  因为往下压 `ki` 会让消静差变慢，往上加 `kp` 会让超调更大；
- 上升时间 70~90 ms 与 wn=10 rad/s 的设计量级吻合，说明参数推导本身是对的。

### CR-001 的量化对比（离线工具 `pid_step_simulate`）

同一组增益、同一对象、同一 `dt`，只切换条件积分开关：

| 配置 | 超调 (%) | 上升 (s) | 整定 (s) | 饱和步数 |
|---|---|---|---|---|
| 无条件积分（= ICD §7 冻结行为） | **29.85** | 0.10 | 0.44 | 13 / 301 |
| 有条件积分（V1.1 候选） | **1.99** | 0.12 | 0.15 | 7 / 301 |

这组数据是 CR-001 的核心证据：**问题不在增益，在算法**。
（工具没有积分限幅参数，绝对数值仅供相对比较；工程真值以本工程的 C 实现与 CSV 为准。）

### 回归验证方式

```powershell

```

超调或整定时间**任一指标劣化超过 20%** 即视为回归，必须给出原因或回退。
